Same servlet, two strategies

Unsafe vs. thread-safe

Both counters live inside the same VisitorCounterServlet and are incremented on every request — only their implementation differs.

NOT THREAD-SAFE

Unsafe Counter

private int unsafeCounter = 0;
  • Uses a normal servlet instance variable
  • Multiple servlet threads access the same variable
  • Read → modify → write happens in three separate steps
  • Can produce race conditions and lost updates
  • Not safe for concurrent requests
THREAD-SAFE

Thread-Safe Counter

private final AtomicInteger safeCounter = new AtomicInteger(0);
  • Uses AtomicInteger instead of a plain int
  • Increment is a single atomic compare-and-swap operation
  • No thread can observe a partial update
  • Prevents lost updates under concurrency
  • Safe for any number of concurrent servlet requests
