Servlet Lifecycle

jakarta.servlet.http.HttpServlet · deployed on Apache Tomcat 10.1+

This lab walks through exactly how a servlet container manages a Java servlet from birth to shutdown — the constructor and init() that run once, the doGet() that answers every request, and the destroy() that cleans up when the app stops. Every action below is backed by a real, deployable servlet — not a simulation.

Four phases, one instance

How the container drives the servlet

The Tomcat container calls these methods in a strict, ordered sequence over the life of a single servlet instance.

PHASE 01

Constructor

Creates the LifecycleServlet instance. Runs exactly once, the moment the container loads the servlet class.

PHASE 02

init()

Initializes the servlet — one-time setup — before it is allowed to handle any client request.

PHASE 03

doGet() / service()

Handles every HTTP GET request. Runs again and again — once per request — for the servlet's entire lifetime.

PHASE 04

destroy()

Releases resources when the servlet is stopped, undeployed, or redeployed by the container. Runs exactly once.
